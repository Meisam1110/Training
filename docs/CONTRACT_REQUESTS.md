# Contract requests (agent · what · why)
- Dev-A · Error codes `unauthorized` (HTTP 401) and `rate_limited` (HTTP 429, with Retry-After) added to the envelope, next to validation|forbidden|not_found|conflict|upstream. Why: a missing/expired session and a locked-out login need distinct, non-403 answers the SPA can route on. Implemented in app/api/errors.py.
- Dev-A · `POST /letters` response shape: returns the first Letter object plus `items: [Letter,...]`. Per-person kinds (level3_request, level3_manager_check) create one letter per enrollment and line_manager_approval one per manager batch (max 9 tickets), so several letters can come back. Please confirm or specify.
- Dev-A · `POST /letters/preview` returns `{kind, subject, html, filename, count}` (no fields, so no PII); institute_letter shows "—" for Letter_No because previews never consume a number.
- Dev-A · `POST /enrollments:bulk` body `{enrollment_ids, run_id?, unassign?, motivation?, registration?, calendar?, attendance?}` -> `{updated:[ids], failed:[{id,reason}]}`; assigning to a run is what turns an IDP request into a participant (used after `candidates:search`). `PATCH /enrollments/{id}` additionally accepts run_id/unassign/payment/comment.
- Dev-A · `POST /runs/{id}/candidates:search` -> `{run_id, course_name, candidates:[Enrollment+flags], excluded:[{enrollment_id,ticket,reason,conflicting_ticket}], total}`; flags: over_motivation_limit, division_change, non_active, level3_eligible.
- Dev-A · Runs are created with `institute` as a NAME (institutes are auto-created; the contract lists no /institutes endpoints). No user PATCH/deactivate endpoint exists in the contract: an admin cannot disable a user via API yet -- request `PATCH /users/{id} {is_active, role, password}`.
- Dev-A · Dev-B: Core calls `factory.build_calendar/build_excel_gateway/build_employee_source/build_email_sender/build_letter_renderer` exactly as listed, and `app.automation.rules.compute_due` (falling back to contracts.compute_due). Letter field dicts are built to match app/documents/specs.py (verified end-to-end for all six kinds in tests/core/test_real_integrations.py). Values Core has no table for come from `PUT /automation/settings` (company_economic_code, company_national_id, company_postal_code, company_address, settlement_addressee, letter_signer_*) or from the letter request's `extra`.
- Dev-A · `connectors.excel` config accepts optional `idp_path` (IDP export synced together with the IFS sheet).
- Dev-B · Letter field names are aligned to Core's list: settlement_letter uses `total`, `start_date_greg`, `rows` (item keys staff_id, description, division_cost_center; `full_name` optional to build description); old names (`invoice_total`, `attendees`, `start_date_gregorian`) are still accepted. Renderer also accepts raw `start_date`/`deadline_date`/`letter_date` (ISO), `duration_hours`, `gender`, `manager_gender`, `reporter_gender` and derives the text fields, so Core may send either form. See docs/TEMPLATES.md.
- Dev-B · `institute_letter` needs organisation constants `company_economic_code, company_national_id, company_postal_code, company_address` (legacy letter footer). They are NOT in the repo: either Core passes them per request (e.g. from a settings row) or an admin creates `templates/letter_defaults.json` (see letter_defaults.example.json); otherwise required_fields() includes them and rendering fails naming them.
- Dev-B · Please add a `lang` argument to Protocol `LetterRenderer.required_fields(kind, lang="both")` (implemented, default keeps current behaviour): for `lang="fa"` or `"en"` only that language's fields are required.
- Dev-B · Dev-A's pyproject `[tool.coverage.run] omit` excludes app/integrations, automation, documents, persian; my tests reach 96% on those packages when run with `coverage run --rcfile=/dev/null --source=app/persian,app/integrations,app/automation,app/documents -m pytest tests/integrations`. Suggest dropping them from `omit`, and adding `aiosmtpd` to the `dev` extra (tests only).
- Dev-B · `SyncReport` has no "rows read" counter; the Excel/IFS readers put parsed-row counts in `created` (rows returned) and `skipped`/`errors`; Core should treat `created` as "rows parsed" for read-only sources and do its own created/updated/unchanged diff.
